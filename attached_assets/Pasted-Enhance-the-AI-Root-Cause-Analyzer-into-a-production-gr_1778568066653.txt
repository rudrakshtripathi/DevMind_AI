Enhance the AI Root Cause Analyzer into a production-grade AI-powered incident investigation and debugging platform that performs deep contextual reasoning, failure correlation, dependency tracing, remediation planning, and intelligent debugging instead of only summarizing logs.

The Root Cause Analyzer should behave like an AI Site Reliability Engineer (SRE), DevOps Engineer, Security Analyst, and Software Architect combined.

The system must:
- Understand stack traces
- Analyze logs contextually
- Trace failure propagation
- Detect primary vs secondary failures
- Correlate multi-service issues
- Explain WHY the issue occurred
- Explain HOW the failure propagated
- Suggest precise remediation steps
- Generate debugging guidance
- Identify security implications
- Recommend preventive measures
- Simulate likely failure chains

The platform should resemble enterprise-grade observability and debugging tools such as:
- Datadog
- New Relic
- Dynatrace
- Splunk
- Elastic Observability
- Sentry
- Grafana
- PagerDuty Incident Intelligence

====================================================
DETAILED INCIDENT ANALYSIS OUTPUT
====================================================

For every incident or failure detected, generate ALL of the following:

1. INCIDENT TITLE
Generate a concise incident name.

Examples:
- Null Pointer Exception in UserService
- Database Connection Pool Exhaustion
- Redis Cache Timeout Failure
- Kubernetes Pod CrashLoopBackOff
- API Authentication Failure
- Out of Memory JVM Crash

2. INCIDENT SEVERITY
Provide:
- Critical
- High
- Medium
- Low
- Informational

Also generate:
- Incident Risk Score out of 10

Example:
Severity: Critical
Risk Score: 9.6/10

3. CONFIDENCE SCORE
Generate:
Confidence: 97%

The confidence should depend on:
- Log clarity
- Stack trace quality
- Correlation certainty
- Failure propagation analysis
- Historical pattern matching

4. ROOT CAUSE ANALYSIS
Generate a highly detailed explanation:
- WHAT failed
- WHY it failed
- WHICH component caused it
- WHICH dependency triggered it
- WHETHER it is primary or secondary failure
- HOW the failure propagated

Example:
“The UserService attempted to access a null object reference because the authentication microservice returned an incomplete payload after a Redis cache timeout. This propagated through the API layer and caused repeated request failures.”

5. PRIMARY vs SECONDARY FAILURE DETECTION
The AI must differentiate:
- root cause
- symptoms
- downstream failures
- unrelated warnings

Example:
PRIMARY:
Redis connection timeout

SECONDARY:
NullPointerException due to missing cached data

6. FAILURE PROPAGATION TIMELINE
Generate an investigation timeline.

Example:
10:00:01 → Redis timeout
10:00:02 → Auth service failure
10:00:03 → NullPointerException
10:00:04 → API returned HTTP 500

Visualize cascading failures.

7. STACK TRACE INTELLIGENCE
Analyze:
- exact failure line
- call hierarchy
- function chain
- recursive loops
- thread crashes
- memory failures

Highlight:
- vulnerable function
- failing module
- probable source file

8. SERVICE DEPENDENCY ANALYSIS
Explain:
- which services interacted
- which dependency failed
- upstream/downstream impact
- API communication breakdown
- network dependency failures

Example:
Frontend
   ↓
API Gateway
   ↓
Auth Service
   ↓
Redis Timeout
   ↓
Authentication Failure

9. INCIDENT IMPACT ANALYSIS
Explain:
- user impact
- service degradation
- downtime risk
- data corruption possibility
- performance degradation
- security implications
- financial/business impact

10. REMEDIATION STEPS
Generate:
- immediate fix
- temporary workaround
- long-term architectural fix
- rollback steps
- validation steps
- monitoring recommendations

Example:
1. Restart Redis cluster
2. Increase timeout threshold
3. Add retry logic
4. Add circuit breaker
5. Implement cache fallback

11. DEBUGGING PLAYBOOK
Generate:
- exact debugging commands
- logs to inspect
- metrics to check
- Kubernetes commands
- Docker inspection steps
- DB verification queries

Example:
kubectl logs pod-name
docker inspect container
top
netstat -tulpn

12. PREVENTION STRATEGY
Generate:
- monitoring recommendations
- alerting rules
- retry mechanisms
- circuit breakers

- failover strategy
- autoscaling recommendations
- rate limiting
